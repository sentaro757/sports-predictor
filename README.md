# 승부예측 대시보드

야구·축구·농구 10개 리그의 일정, 결과, 뉴스, 부상, 영입·방출 소식을 모아서 경기 승부를 예측하는 웹 대시보드입니다.

| 종목 | 리그 | 데이터 출처 |
|---|---|---|
| ⚾ 야구 | KBO, MLB | 네이버 스포츠, ESPN |
| ⚽ 축구 | K리그1, 프리미어리그, 라리가, 분데스리가, 세리에A, 리그1 | 네이버 스포츠, ESPN |
| 🏀 농구 | KBL, NBA | 네이버 스포츠, ESPN |

## 실행

Node.js 20 이상이 필요합니다.

```bash
npm install
npm start
```

브라우저에서 http://localhost:3000 을 엽니다. 리그를 처음 열 때는 과거 경기를 수집하느라 10~20초 걸리고, 그 뒤로는 캐시(`data/cache`)를 씁니다.

- `npm run check`: 모든 리그의 수집과 예측을 점검합니다. 리그 하나라도 실패하면 종료 코드 1로 끝나고, 일부 수집 실패나 오래된 캐시 사용 같은 경고도 출력합니다(대시보드 상단에도 표시).
- `npm test`: 코드 리뷰(REVIEW.md)에서 지적된 문제들의 회귀 테스트입니다.

기본적으로 **이 PC에서만** 접속할 수 있습니다(127.0.0.1). 같은 네트워크의 다른 기기에서 쓰려면 접속 토큰을 함께 설정하고, 첫 접속 주소에 `?token=...` 을 붙입니다.

```powershell
$env:HOST = "0.0.0.0"; $env:ACCESS_TOKEN = "아무도-모를-긴-문자열"; npm start
```

## 예측 방식

1. **Elo 전력 지수**: 경기 결과와 점수차로 팀 레이팅을 계산합니다. 사용하는 기간은 국내 리그 약 18개월, MLB·NBA 이번+지난 시즌, 유럽 축구 이번+지난 두 시즌입니다.
   - 시즌 구분은 ESPN의 시즌 정보, 국내 리그는 KST 날짜 기준 시즌 연도로 합니다. 새 시즌 첫 경기 전부터 레이팅을 평균 쪽으로 일부 되돌리고 폼을 비웁니다.
   - 축구 승격팀은 리그 평균보다 100점 낮게 시작합니다. 강등된 팀과의 지난 시즌 경기도 빠짐없이 포함합니다.
2. **홈 어드밴티지**: 종목별로 다르게 줍니다.
3. **축구 승/무/패**: Elo 차이를 기대 득점 차이로 바꾸고 포아송 분포(Dixon-Coles 저득점 보정)로 확률을 냅니다. 리그별 평균 득점과 보정값은 과거 경기의 로그 손실이 가장 낮도록 맞춥니다.
4. **최근 폼**: 최근 5경기 성적을 반영합니다.
5. **부상자**: MLB, NBA는 ESPN 부상자 명단을 씁니다. 같은 선수는 한 번만 셉니다. 선수가 명단에 처음 보인 시점(또는 ESPN 업데이트 시점) 이후 팀이 치른 경기 수를 기록해서, 이미 결장한 경기만큼은 그 공백이 성적(Elo)에 반영됐다고 보고 감점을 줄입니다(1경기당 7%, 최대 70%). 방금 생긴 부상은 복귀 예정일이 멀어도 전액 감점합니다.
6. **뉴스 신호**: 최근 3일 기사에서 부상·결장·감독 교체는 악재로, 복귀·합류는 호재로 봅니다. 기사 수가 아니라 **사건 수**를 셉니다: 같은 선수의 부상 기사가 여러 건이어도 1건이고(선수를 모르면 같은 날 같은 유형을 1건으로), 같은 선수에게 부상과 복귀가 둘 다 있으면 최근 기사를 따릅니다. 또 부상 명단이 있는 리그는 기사 속 부상을 따로 세지 않습니다. 기사가 **어느 팀 이야기인지**는 아래 "기사 대상 팀 판단" 참고.

7. **시범경기**: NBA·MLB 시범경기는 표시를 붙이고 확률을 50:50 쪽으로 절반 당깁니다.
8. **사후 검증**: 경기마다 "그 경기 직전의 Elo+홈 어드밴티지로 예측했다면 맞혔는지"를 기록해 적중률과 로그 손실을 보여줍니다. 폼·부상·뉴스 보정은 과거 시점의 기사·부상 기록이 없어서 검증에 포함되지 않습니다(화면에도 "Elo+홈 백테스트"로 표시). 축구 확률 보정값은 평가하는 시즌 이전 경기로만 맞춥니다.

종목별 파라미터는 `src/config.js` 의 `MODEL` 에서 바꿀 수 있습니다.

## 기사 대상 팀 판단

"삼성전 앞둔 LG 주전 부상"처럼 한 기사에 여러 팀이 나올 때, 부상·복귀·감독 교체가 실제로 어느 팀의 일인지 정합니다.

**규칙 기반 (기본)** — `src/signals.js`
1. 제목과 요약을 따로 보고, 요약의 사진 설명·기자 표기는 지웁니다. 제목이 판단한 팀은 요약이 덮어쓰지 않습니다.
2. 신호 키워드가 있는 **절** 안에서만 대상을 찾습니다(쉼표·말줄임표·따옴표 등으로 구분). 없으면 앞 절로 거슬러 올라갑니다.
3. **선수 이름 → 소속팀** 사전을 가장 강한 근거로 씁니다(KBO·K리그는 네이버, 해외 리그는 ESPN 명단). "이탈로(제주)" 같은 `선수(팀)` 표기도 인식합니다. KBL은 명단 API가 없어 팀 이름만 씁니다.
4. 팀 이름의 역할을 조사·전치사로 구분합니다: "LG**는**/LG**의**/Chelsea**'s**"는 주체, "삼성**을**/삼성**에**/삼성**과**/삼성 **상대로**/삼성**전**/**against** Chelsea"는 상대팀(제외).
5. 부정·관용 표현을 처리합니다: "복귀 불발", "not available" → 악재 / "부상 털고", "큰 부상은 피했다", "despite injuries" → 신호 아님 / "3위 복귀", "bounce back", 감독의 복귀 → 선수 복귀 아님.
6. 근거가 비슷하게 갈리면 어느 팀에도 붙이지 않습니다(틀리게 붙이는 것보다 낫기 때문).

**AI 기사 분류** — `src/ai-tagger.js`
문장의 뜻을 이해해야 하는 경우("코칭 제안을 거절하다 발렌시아가 부르자 수락" = 발렌시아 감독 선임)는 규칙으로 풀 수 없습니다. Claude가 기사마다 팀과 사건을 분류하면 그 결과가 규칙보다 우선합니다.

- **자동으로 돌지 않습니다.** 경기 상세 화면에서 **AI 분석 실행**을 누르면, ① Haiku가 그 경기 두 팀의 최근 3일 기사 중 아직 분류하지 않은 것만 먼저 분류하고 ② Opus가 그 결과로 분석합니다(아래 "AI 뉴스 분석").
- 결과는 `data/state/ai-tags-<리그>.json` 에 저장해 같은 기사를 다시 보내지 않으며, 같은 팀의 다른 경기 예측에도 반영됩니다.
- 모델은 `AI_TAG_MODEL`(기본 `claude-haiku-5-5`), 하루 최대 40회 호출(`AI_TAG_DAILY_LIMIT`). 분류 없이 분석만 하려면 `AI_TAG_ARTICLES=0`.
- AI가 분류한 기사에는 "AI 판단" 표시가 붙습니다.

**정확도 확인**
- `node scripts/eval-attribution.js`: 까다로운 문장 31개 평가 세트(`test/fixtures/attribution.json`). `npm test`에도 포함됩니다.
- `node scripts/eval-real.js`: 실제 기사로 만든 로컬 검증 세트. 기사 원문이 들어 있어서 git에 올리지 않습니다(`test/fixtures/*.local.json`).

## AI 뉴스 분석 (선택)

API 키를 설정하면 경기 상세 화면에 **AI 분석 실행** 버튼이 생깁니다. 누르면 ① Haiku가 두 팀 기사를 분류(위 "AI 기사 분류")하고 ② Opus가 부상, 이적, 팀 기사의 내용을 읽고(예: 빠진 선수가 주전인지, 선발투수가 누구인지) 통계 확률을 보정한 뒤 이유를 한국어로 설명합니다. 결과 아래에 단계별 비용이 나옵니다. 버튼을 누르지 않으면 AI 비용은 전혀 들지 않습니다.

```powershell
$env:ANTHROPIC_API_KEY = "sk-ant-..."
npm start
```

- 기본 모델은 `claude-opus-5-5` 입니다(`AI_MODEL` 로 변경).
- 같은 경기는 3시간 동안 다시 분석하지 않습니다(캐시).
- 비용 안전장치: 하루 최대 30회(`AI_DAILY_LIMIT` 으로 조정), 동시에 2건까지만 실행합니다. 하루 호출 수는 `data/state/ai-limits.json` 에 저장되어 서버를 다시 켜거나 두 개를 띄워도 유지됩니다. API 요청을 보내기 전에 한 칸을 예약하고, 결과(성공·실패·재시도)와 상관없이 그대로 셉니다.
- AI가 낸 확률은 통계 예측에서 AI 쪽으로 "한 비율만큼만" 옮겨서, 최종 확률의 모든 결과가 통계 대비 ±15%p 안에 들고 합계도 1로 유지됩니다.
- 분석 중에 창을 닫거나 다른 경기를 열면, 늦게 도착한 결과는 버립니다(다른 경기 화면에 붙지 않음).
- 기사 내용은 신뢰할 수 없는 외부 데이터로 표시해 전달하고, AI가 낸 확률은 통계 예측에서 결과별 ±15%p 안으로 제한합니다. 형식이 잘못된 응답은 한 번 다시 시도하고, 그래도 안 되면 통계 예측을 그대로 보여줍니다.
- AI가 요청을 거절하면 서버 쪽에서 다른 모델로 자동으로 다시 시도합니다(`fallbacks: "default"`).

## AI 비용

승부 확률 계산(Elo 통계모델)은 무료입니다. 비용은 경기 상세의 **AI 분석 실행** 버튼을 누를 때만 생깁니다(기사 분류 + 분석).

| 기능 | 기본 모델 | 1회 대략 비용 |
|---|---|---|
| AI 분석 버튼 1회 (경기 1개, 분류 포함) | `claude-opus-5-5` | 몇 센트 |
| └ 그중 ① 기사 분류 (두 팀 기사, 30건당) | `claude-haiku-5-5` | 약 $0.003 |

- 화면 오른쪽 위에 **오늘 / 이번 달 비용**이 나오고, 누르면 기능·모델별 호출 수, 토큰 수, 금액이 나옵니다. AI 분석 결과에도 그 분석의 비용이 표시됩니다.
- 금액은 API 응답에 기록된 **실제 토큰 수 × 정가**로 계산하고 `data/state/ai-usage.json` 에 날짜별로 쌓습니다(120일 보관). 원화는 `USD_KRW`(기본 1400) 환율로 환산한 대략값이고, 실제 청구액은 Anthropic 콘솔에서 확인하세요.

## 팀 공식 홈페이지 뉴스 추가

구단 사이트마다 구조가 달라서 직접 스크래핑하면 쉽게 깨지므로, RSS/Atom 피드를 등록하는 방식으로 만들었습니다. `data/team-feeds.json` 에 리그 ID, 팀 ID, 피드 주소를 넣으면 해당 팀 뉴스에 "구단 공식" 표시와 함께 섞여 나옵니다. 팀 ID는 경기 상세 화면의 팀 이름 옆에 나옵니다.

```json
{
  "epl": { "359": "https://example.com/arsenal/news.rss" }
}
```

## 저장되는 파일

- `data/cache/`: 네트워크 응답 캐시. 14일 지난 파일은 시작할 때 자동 삭제됩니다. 지워도 다시 받아옵니다.
- `data/state/`: 오래 보관하는 상태 — AI 비용 기록(`ai-usage.json`, 120일), AI 기사 분류(`ai-tags-*.json`, 14일), 부상 추적(`injuries-*.json`), AI 호출 한도(`ai-limits.json`). 캐시 청소 대상이 아닙니다.

## 한계

- 국내 리그(KBO, K리그, KBL)와 유럽 축구는 공개된 부상자·이적 명단이 없어서 기사에서 자동으로 골라냅니다. 그래서 정확도가 MLB, NBA보다 낮습니다.
- 야구의 선발투수, 축구의 로테이션 같은 경기별 라인업은 통계모델에 들어가 있지 않습니다. AI 분석이 기사를 통해 일부를 보완합니다.
- 네이버와 ESPN의 공개 API는 공식 지원되는 API가 아니어서 예고 없이 바뀔 수 있습니다. 개인 용도로만 쓰고, 요청 빈도는 캐시로 낮춰 두었습니다.
- 예측은 참고용입니다.

## 구조

```
server.js            HTTP 서버와 API 라우팅
src/config.js        리그 목록과 모델 파라미터
src/sources/         naver.js, espn.js, feeds.js (데이터 수집)
src/model.js         Elo, 포아송(축구), 보정, 사후 검증
src/signals.js       뉴스 키워드 분류, 부정문 처리, 기사 대상 팀 판단 (규칙)
src/ai-tagger.js     기사 대상 팀·사건 AI 분류 (선택)
src/service.js       리그별 데이터 취합과 경기 상세
src/ai.js            Claude 경기 분석 (선택)
src/usage.js         AI 사용량·비용 기록
src/limits.js        AI 하루 호출 한도 (저장, 프로세스 간 공유)
src/injury-tracker.js 부상 결장 시작 시점·결장 경기 수 추적
src/store.js         data/state/ 저장소 (원자적 저장, 파일 잠금)
public/              대시보드 화면
test/                회귀 테스트 (npm test)
```
